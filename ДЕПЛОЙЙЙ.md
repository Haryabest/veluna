# Veluna — деплой и запуск на новом ПК

Инструкция: **локальная разработка + Telegram Mini App** (Pinggy) и **продакшен на сервере** (Docker).

---

## Что нужно заранее

| Софт | Версия | Зачем |
|------|--------|--------|
| Git | любая | клон репозитория |
| Docker Desktop | актуальная | PostgreSQL, Redis, MinIO |
| Node.js | 20+ | frontend |
| Python | 3.12+ | backend и бот |
| OpenSSH (`ssh`) | в Windows | туннель Pinggy |

Опционально: `winget` — скрипт бота сам поставит Python, если нет.

---

## Часть 1. Новый ПК — локальная разработка (как у вас сейчас)

### Шаг 0. Клон

```powershell
git clone <url-репозитория> veluna
cd veluna
```

### Шаг 1. Один раз — окружение

```powershell
.\scripts\setup-env.ps1
```

Создаст `.env` и `frontend\.env.local` (если их ещё нет) и пропишет `127.0.0.1` для БД/Redis.

**Обязательно отредактируйте `.env`:**

- `TELEGRAM_BOT_TOKEN` — токен из [@BotFather](https://t.me/BotFather)
- `SECRET_KEY`, `JWT_SECRET_KEY` — длинные случайные строки (можно скопировать со старого ПК)
- `ADMIN_TELEGRAM_IDS` — ваш числовой Telegram ID (для админки)

> Файл `.env` в Git **не попадает**. На новом ПК его копируют вручную или заполняют заново.

### Шаг 2. Один раз — зависимости

```powershell
# Инфраструктура
docker compose up postgres redis minio -d

# Backend
cd backend
py -3.12 -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
.\.venv\Scripts\alembic upgrade head
cd ..

# Frontend
cd frontend
npm install
cd ..
```

### Шаг 3. Каждый рабочий день — 4 процесса

Откройте **4 терминала** в корне `veluna`:

| # | Команда | Что делает |
|---|---------|------------|
| 1 | `docker compose up postgres redis -d` | БД (если ещё не запущены) |
| 2 | `cd backend; .\.venv\Scripts\uvicorn app.main:app --reload --host 0.0.0.0 --port 8000` | API |
| 3 | `cd frontend; npm run dev` | Mini App на http://localhost:3000 |
| 4 | `.\scripts\run-bot-local.ps1` | Telegram-бот (оплата Stars, /start) |

### Шаг 4. Туннель для Telegram (HTTPS)

Telegram открывает Mini App **только по HTTPS**. Локально — Pinggy:

```powershell
.\scripts\dev-miniapp-up.ps1
```

1. Откроется окно **«Veluna Pinggy»** (смотрите панель задач).
2. На запрос пароля — **Enter** (пустой).
3. Дождитесь URL вида `https://xxxx.run.pinggy-free.link`.
4. Скрипт сам обновит `.env`, `frontend\.env.local` и кнопку меню бота.

**Окно Pinggy не закрывайте** — пока оно открыто, туннель жив.

Если URL уже виден:

```powershell
.\scripts\dev-miniapp-up.ps1 -Url "https://ВАШ-URL.run.pinggy-free.link"
```

Проверка туннеля:

```powershell
.\scripts\tunnel-status.ps1
```

### Шаг 5. Проверка

1. В Telegram: бот → кнопка **«Открыть Veluna»** (не браузер на localhost).
2. Магазин / оплата Stars — только из Telegram, бот должен быть запущен (терминал 4).
3. API: http://127.0.0.1:8000/docs

## Часть 2. Что переносить со старого ПК

| Перенести | Не переносить |
|-----------|----------------|
| `.env` (токены, секреты) | `node_modules`, `.venv`, `.next` |
| Тот же `TELEGRAM_BOT_TOKEN` | Старый Pinggy URL |
| По желанию — дамп PostgreSQL | `.pinggy.log`, `.tunnel-url` |

Копирование `.env`:

```powershell
# со старого ПК на флешку / в облако, затем в корень veluna на новом ПК
```

## Часть 3. Продакшен (VPS / сервер)

Стабильный URL для пользователей — **без Pinggy**.

### Требования

- Сервер с Docker и Docker Compose
- Домен с HTTPS (Let's Encrypt или Cloudflare)
- В BotFather: Web App URL = `https://ваш-домен.com`

### Запуск

```bash
git clone <url> veluna && cd veluna
cp .env.example .env
# заполнить .env: SECRET_KEY, JWT, TELEGRAM_BOT_TOKEN, TELEGRAM_WEBAPP_URL=https://домен
# DATABASE_URL и REDIS_URL — как в docker-compose (хосты postgres, redis)

docker compose up -d --build
docker compose exec backend alembic upgrade head
docker compose up -d telegram-bot
```

Открыть:

- Сайт / Mini App: ваш домен (через nginx из compose)
- API docs: `https://домен/api/v1` или порт backend по вашей схеме

### Frontend в продакшене

В `.env` для production:

```env
NEXT_PUBLIC_API_URL=https://ваш-домен.com/api/v1
TELEGRAM_WEBAPP_URL=https://ваш-домен.com
```

Пересобрать frontend-образ после смены переменных.

## Часть 4. Частые проблемы

| Симптом | Решение |
|---------|---------|
| `dev-miniapp-up` «висит» | Смотрите окно **Veluna Pinggy** на панели задач; ждите до 90 с или вставьте URL вручную |
| `Frontend not on :3000` | Сначала `cd frontend; npm run dev` |
| Mini App пустой / 401 | Открывать **из Telegram**, не из Chrome на localhost |
| Оплата Stars не зачисляет гемы | Запущен ли `run-bot-local.ps1` (или `telegram-bot` в Docker) |
| В `.env` попал `dashboard.pinggy.io` | Запустите `dev-miniapp-up` заново или `-Url` с правильным `*.pinggy-free.link` |
| Бот не отвечает при VPN | Бот на **хосте** (`run-bot-local.ps1`), не в Docker — так и задумано |
